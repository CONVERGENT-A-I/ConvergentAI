# Migration Plan: OpenAI Realtime (S2S) to LiveKit Inference Cascaded Pipeline

This document describes the implementation steps to migrate the Ailana backend voice pipeline from the legacy **OpenAI Realtime Speech-to-Speech (S2S)** model (`gpt-realtime-mini` / `gpt-4o-mini-realtime-preview`) to a **Cascaded Pipeline (STT -> LLM -> TTS)** using LiveKit Inference + Groq (Llama 3.3 70B Instruct) + Cartesia (Sonic 3.5).

---

## 1. Architectural Overview & Voice Continuity

To preserve all current prompting mechanics, context-compaction limits, structured fact logging, session rotation, and state management, the migration changes *only* the voice model instantiation inside the LiveKit agent worker loop.

```
                  ┌──────────────────────┐
                  │ User Speaking Audio  │
                  └──────────┬───────────┘
                             │
                             ▼
                ┌──────────────────────────┐
                │ STT: Cartesia Ink-2      │
                └──────────┬───────────授──┘
                             │ (Text Transcript)
                             ▼
                ┌──────────────────────────┐
                │ Turn Detector v1         │ (Intelligent End-of-Turn VAD)
                └──────────┬───────────授──┘
                             │ (Turn Confirmed)
                             ▼
                ┌──────────────────────────┐
                │ LLM: Groq Llama 3.3 70B  │ (Static buildVoiceInstructions())
                └──────────┬───────────授──┘
                             │ (Text Stream)
                             ▼
                ┌──────────────────────────┐
                │ TTS: Cartesia Sonic 3.5  │ (Locked Ailana Voice ID)
                └──────────────────────────┘
```

### Core Constraints & Rules
*   **Prompt Stability**: The existing system prompts (`buildVoiceInstructions()`) and user greeting/resumption parameters are unchanged.
*   **Voice continuity**: The Cartesia voice ID is locked to `AILANA_VOICE_ID` from the environment and remains constant throughout the session.
*   **Compaction / Rotation**: Context-broker state compaction and rotate checks will remain fully operational using standard chat history logs generated by the cascaded pipeline.
*   **Rollback Strategy**: Controlled by the `USE_CASCADED_PIPELINE` flag in the environment. Setting it to `false` will seamlessly fall back to the legacy S2S pipeline.

## 4. Implementation Steps

### Step 4.1: Update [ailana-config.ts](file:///c:/Users/SOHAIL/Downloads/ConvergentAI/backend/src/config/ailana-config.ts)
*   Expose the feature flag `useCascadedPipeline`.
*   Expose `groqApiKey` and `cartesiaKey`.
*   Expose `cartesiaVoiceId` (with default fallback to Sarah).

### Step 4.2: Update [agent.ts](file:///c:/Users/SOHAIL/Downloads/ConvergentAI/backend/src/agent.ts)
*   **Import the Cartesia Plugin**: `import * as cartesia from '@livekit/agents-plugin-cartesia';`
*   **Update `createVadAgent()`**:
    *   If `ailanaConfig.useCascadedPipeline` is `true`, return a cascaded `voice.Agent`:
        *   `stt`: `new cartesia.STT({ model: 'cartesia/ink-2', apiKey: ailanaConfig.cartesiaKey })`
        *   `llm`: `new openai.LLM({ model: 'llama-3.3-70b-versatile', baseURL: 'https://api.groq.com/openai/v1', apiKey: ailanaConfig.groqApiKey })`
        *   `tts`: `new cartesia.TTS({ model: 'cartesia/sonic-3.5-latest', voice: ailanaConfig.cartesiaVoiceId, apiKey: ailanaConfig.cartesiaKey })`
        *   `turnHandling`: Turn detection set to `'multilingual'` (Turn Detector v1) with eager end-of-turn pre-warming.
    *   Otherwise, return the legacy Silero VAD + OpenAI Realtime S2S agent.
*   **Update Session Instantiation**:
    *   If cascaded pipeline is enabled, initialize the `AgentSession` without a pre-bound `llm` (since the LLM is managed by the `Agent` itself).
*   **Update Metrics Handlers**:
    *   Ensure that LLM metrics (`llm_metrics` type) are tracked in the metrics collector alongside `realtime_model_metrics` to prevent compaction or latency tracking exceptions.

## 5. Verification & Testing

### Automated Checks
*   Run `npm install` inside the `backend/` directory to fetch the Cartesia plugin.
*   Compile the backend code (`npm run build`) to ensure all types are valid.

### Staging Verification
1.  Launch the backend server (`npm run dev`) and watch the boot logs.
2.  Join a voice room to trigger agent connection.
3.  Verify the connection greeting ("Hello, I'm Ailana...") sounds identical using the Cartesia Locked Voice.
4.  Engage in conversation and verify that turn interruptions, fact-compaction logging, and stage transitions function exactly as before.
